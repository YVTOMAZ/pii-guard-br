# Segurança

## Como reportar uma vulnerabilidade

Use **GitHub Security Advisories** (aba "Security" do repositório) para reportar
de forma privada. Não abra issue pública com detalhes de exploração, prova de
conceito ou dados reais.

Se os Security Advisories não estiverem disponíveis para você, abra uma issue
genérica pedindo um canal privado, sem incluir detalhes técnicos.

## Prazo

Resposta em **melhor esforço em 7 dias úteis**. Não há SLA garantido.

## O que incluir no reporte

- Descrição do problema e impacto.
- Passos de reprodução com **dados sintéticos**.
- Versão/commit afetado.
- Sugestão de correção, se houver.

## O que não fazer

- Não incluir CPF, CNPJ, e-mail, telefone, nomes ou outros dados pessoais
  reais.
- Não publicar exploit antes de uma correção estar disponível.
- Não enviar segredos, tokens ou credenciais.

## Escopo

Este projeto mascara PII em texto, planilhas e imagens. Vulnerabilidades
relevantes incluem: bypass de mascaramento, vazamento de dados em logs/cache,
armazenamento inseguro de segredos e execução não autorizada de comandos.

Relate também problemas que afetem a preservação da licença MIT e da
atribuição a Lucas Aguilar / pii-tokens, quando relevantes para segurança.
